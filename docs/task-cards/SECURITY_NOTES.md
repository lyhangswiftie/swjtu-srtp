# SecureCodeAct 安全注意事项 (Security Notes)

本文档记录了 SecureCodeAct (SCA) 在部署和运行过程中的核心安全注意事项，特别针对生产环境和对外暴露的服务。

## 1. 凭证注入安全

在 v3.2 及以上版本中，我们对 GitHub Token 等敏感凭证的注入机制进行了硬化：

- **禁止命令行传参**：绝不通过命令行参数（如 `curl -d '{"token": "..."}'`）传递 Token，防止被 `ps aux` 或 `/proc` 窥探。
- **临时文件机制**：使用 `mktemp` 创建临时文件传递 JSON payload。
- **严格权限控制**：临时文件创建后立即执行 `chmod 600`，确保仅当前用户可读写。
- **强制清理**：使用 `trap RETURN` 机制，确保脚本在任何情况下退出（正常或异常）都会清理包含 Token 的临时文件。
- **日志脱敏**：安装日志中不再打印 Token 的任何片段（包括前 4 位），仅提示“检测到 GitHub Token”。

## 2. 文件系统与挂载安全

- **Volume Mount 校验**：在使用 Docker volume mount 挂载本地文件到容器内覆盖默认行为时，脚本会强制检查本地文件是否存在（Fail-fast 机制）。若文件缺失直接 `exit 1`，避免静默回退导致安全策略失效。
- **配置目录权限**：自动生成的 `~/.openhands` 配置目录被强制设置为 `700` 权限，防止其他系统用户读取敏感配置。

## 3. 依赖包安装安全

- **严格指定版本**：在 `install.sh` 和 `requirements.txt` 中，所有核心依赖均指定了最小安全版本（如 `"PyYAML>=6.0.2"`、`"requests>=2.32.3"`）。
- **防止参数注入**：`pip install` 时的包名强制使用双引号包裹，防止恶意环境变量导致的包名注入攻击。

## 4. 沙箱容器安全隔离

- **网络权限**：为解决 WSL2 等环境下的沙箱子容器 iptables 报错，我们统一添加了 `--cap-add NET_ADMIN --cap-add NET_RAW` 权限。请注意，这会增加容器的网络特权，在多租户共享主机环境中应谨慎评估。
- **Host Network 模式**：为规避部分环境的网络隔离问题，当前默认使用 `--network host` 启动主容器。在生产部署时，建议使用自定义桥接网络并严格配置端口映射。

## 5. 前端与 API 暴露风险

- **无身份验证 API**：当前架构下，SCA-HUD 前端直接与后端的 `/api/*` 接口通信，且默认不包含强制的身份验证中间件。**切勿将 3000 端口直接暴露在公网**。
- **建议的生产架构**：在生产环境中，必须在 SCA 前置 Nginx/Caddy 等反向代理，并配置 Basic Auth 或 OAuth2 认证，同时启用 HTTPS (TLS)。

## 6. 持续监控与审计

建议定期运行 `scripts/sca_doctor.sh` 脚本，检查环境配置、依赖版本和容器状态是否符合安全基线。
