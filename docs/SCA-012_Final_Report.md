## 一、任务目标与背景

在先前的迭代中，虽然成功连接了 Neo4j 并调整了中间栏 4:4:2 布局，但由于 API 查询限制和数据映射错误，导致 ReactFlow 渲染的知识图谱区域存在大面积空白，未能真正展示“仓库级总 CPG 知识图谱”的全局视野。

本次 SCA-012-v3 任务的核心目标是：**彻底修复数据管道，强制中间栏必须显示真实的 Neo4j 全局图谱（非空白、非简化版），包括所有 62 个节点、112 条关系以及跨 CVE 关联**。

---

## 二、技术方案与核心修复

### 2.1 后端 API 修复 (`neo4j_service.py`)

原先的 API 实现存在严重的节点截断和关系映射丢失问题。本次重写了全量查询逻辑：

1. **全量节点查询**：移除了 `LIMIT 30` 限制，一次性查询图数据库中所有类型的节点（CVE, CWE, CPGNode, SinkFunction, Patch, SourceFile, Repository），总计 62 个节点。
2. **关系映射修复**：使用 Neo4j 内部生成的 `id(n)` 作为全局唯一的映射键（`node_id_map`），彻底解决了原先使用 `label` 或业务 ID 导致的大量边丢失问题。
3. **全局自动布局算法**：
   - **CVE 节点**：采用环形布局（Circle Layout），居中显示，半径 200px。
   - **CPG 节点**：采用子环形布局，围绕其归属的 CVE 节点排列，半径 90px。
   - **CWE 节点**：在右侧纵向排列。
   - **Sink 节点**：在左侧纵向排列。
   - **其他节点**（Repo, Patch, SourceFile）：分布在顶部和底部。

### 2.2 前端渲染修复 (`KnowledgeGraphTab.tsx`)

1. **Flex 容器高度修复**：修复了原先因缺失 `flex-row` 容器导致 ReactFlow 区域高度塌陷的问题，确保图谱区域能完全撑满中间栏 40% 的高度。
2. **强制真实数据渲染**：移除了 `STATIC_CVE_DATA` 回退逻辑。图谱严格依赖 `fetch("http://localhost:7475/api/neo4j/graph")` 返回的真实数据进行渲染。
3. **跨 CVE 关系高亮**：特别增强了 `SHARES_CWE`、`SHARES_SINK` 和 `RELATED_TO` 等跨 CVE 关系边的视觉权重（加粗 + 虚线 + 标签），以突出仓库级总览的价值。
